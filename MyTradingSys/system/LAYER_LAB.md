# Layer lab: Codex as the independent checker of the Tom and Fabio layers (operator 2026-10-12)

Why: Claude wrote the encoding, its tests and its backtests, and the coded Tom still fired on 0 of 7 of his own trades
(research/tom_transfer_2026-10-11/ROADMAP.md F1). A different model checks the same work. Rules are not copied here:
AGENTS.md -> CLAUDE.md; protocol PARALLEL.md; plan of record for the layers is that ROADMAP.md.

## Scope
In: the trader layers being redefined (Tom, Fabio; later the home-fit audits), their specs, ledgers, encodings, backtest code and reports.
Out: the live path, the relay (`NEXT_SESSION.md`, scheduled tasks), writing a layer spec (Opus research), reading video frames
(they exist only on JIS-NB: post a desk task), any holdout read, anything in ROADMAP.md section 2 (STOP now).

## Three kinds of card (lane `CODEX`, field `kind`)
| kind | job | model / effort (tasks.CODEX_KINDS) | must have |
|---|---|---|---|
| `audit` | check a spec, ledger, encoding or backtest report against its sources and backtest/PRE_REG_TEMPLATE.md; changes nothing | gpt-6-astra / high | scope_in |
| `run` | run given backtest or recall commands on development data, report the numbers | gpt-6-luna / low | commands |
| `build` | code from a card, test red first, behind a flag that is off | gpt-6.1-sol / medium | tests |
A card may name its own `model` or `effort` (low, medium, high, xhigh, max). The strong model spends the trial faster: keep it for audits.

## How work gets in and out
- Ask: `python scripts/dev/codex_run.py ask "<what you want checked or run>" --kind audit --scope <repo path>` writes a ready card
  (steps, scope_out and done_when come from the kind's template); commit and `sync.py ship`. Any Claude session does this for an Inbox item.
  In the Codex app (project folder `F:\MTS\mts-codex`) the operator can type the ask directly; Codex writes the card the same way, then works it.
- Run: Windows task `MTS-CodexLab` on JIS-NUC runs `codex_run.py tick` (refresh `F:\MTS\mts-codex-lab` on branch `jis-nuc/codex-lab`,
  take the first ready unclaimed CODEX card, start `codex exec` with the card's model and effort). No card = no Codex call, no cost.
  One run at a time (lock). A card that fails twice without ending `done` is STUCK and skipped until someone looks (`codex_run.py status`).
- Deliver: one report per card in `research/layer_lab/reports/<UTC date>_<card>.md`, the card's `result` line, and
  `research/layer_lab/INDEX.md` (newest first, regenerated by `codex_run.py index`). `sync.py news` shows the commit.
- Pause: `codex_run.py stop "<why>"`, `resume`. Run log and per-run output: `%CODEX_HOME%\lab_runs\`.
- `tasks.py next` without `--lane` hides CODEX cards, so Claude relay sessions never take them; the claim is still the lock.

## Report format
1. Verdict line: `SOUND` / `FIX-FIRST` / `BLOCKED` (audit), or the headline numbers (run), or changed files + test output (build).
2. What was checked or run: files with line ranges, commands, data range.
3. Findings table: severity HIGH/MED/LOW, file:line, what is wrong, evidence (quote or number), proposed fix. Every claim is
   MATCH / MISMATCH / NOT_IN_DATA against a file that was read; nothing from memory.
4. Follow-up cards created (ids).

## Backtest discipline (a "run" card can ask for anything except these)
- Development data only. The holdout is read once, by the pre-registered card, never by the lab.
- Every run is a trial: one row in `research/layer_lab/TRIALS.md`. A result picked from many unlogged runs is not a result.
- No BTC run of the current Tom or Fabio encoding, no tuning (ROADMAP.md section 2). Missing input = NOT_IN_DATA, never 0.
- Data on JIS-NUC (CODEX_BRIDGE.md): no `tom_videos` / `fabio_videos`; `dax_archive` must be rebuilt first with backtest/dax_data.py.
