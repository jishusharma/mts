# Card spec: state-code-accumulator-backfill

## Goal
StateCodeEmitter loses ticks after a restart or WS reconnect: session CVD (-367 BTC off) and VWAP sums (26.8% volume missing) are partial-session values shown as session values (audit M1/M2). On start and on every WS reconnect re-seed session_cvd/cum_pv/cum_vol from fapi 1m klines (UTC day start to the last closed minute) stitched to live ticks without double count or gap; while the backfill is missing, failed or incomplete the accumulators are INVALID and the two signals that use them are unavailable (null), never partial.

## Steps
1. Read the audit M1/M2 + Control test, StateCodeEmitter.java onOpen/onMessage/onClose/scheduleReconnect (~112-168), applySessionAccumulator (~176-189), computeCvdSlope cvd ring (~340-357), signals + MIN_SIGNALS (~244), persist/restore (~426-431, ~470-476) and the klines call in BinanceClient.java.
2. Backfill (OURS): fapi 1m klines of CLOSED bars from the UTC day start to the last closed minute boundary M (<= 1440 bars, one request): cvd = sum(2*takerBuyBase - volume), cum_vol = sum(volume), cum_pv = sum(quoteVolume). Expected bar count = (M - dayStart)/60000; any other count, HTTP/JSON error or timeout = failure.
3. Seam: from the moment a gap can exist (start, onClose) accumulators are INVALID and incoming ticks are buffered, not summed; after a successful backfill sum only buffered/live ticks with T >= M and drop earlier ones; restored sums from state_code.json are never added to, they only mark the accumulators INVALID until the backfill succeeds. Backfill runs off the WS thread; retry every 30 s while INVALID (OURS), log each failure.
4. Fail closed: emit session_accumulators_valid and a reason string; while INVALID the cvd_slope and price_vs_vwap signals are null; clear the cvd ring on every invalidate and on backfill completion so the jump cannot read as slope; UTC day rollover with a continuous stream resets to zero as today, rollover while INVALID re-runs the backfill for the new day.
5. Write the done_when a-f tests first, run on old code to see them fail, then implement; mvn -q test -Dtest=StateCodeEmitterTest; run_all_tests --quick; ship. Deploy by hand only after the GPT-high cross-vendor code review (note), per DEPLOY_RUNBOOK.md, with a restart window.

## Done when

(a) After a restart with stale restored sums the emitted sums equal the kline totals + post-boundary ticks, not restored + backfill. (b) WS reconnect gap: sums equal kline totals + ticks with T >= M (M = last closed minute boundary); a tick with T < M is not counted twice. (c) Backfill API error, timeout, short kline list (count != expected closed minutes), duplicate or non-monotonic openTime: state_code.json has session_accumulators_valid=false, cvd_slope and price_vs_vwap are null, and valid recovers on a later successful retry. (d) Continuous control (no gap): sums equal the plain tick sums exactly (existing behaviour unchanged). (e) Non-aggTrade message on the stream leaves the sums unchanged. (f) Replay fixture whose klines are built from the same ticks: emitted CVD within 0.1 BTC of kline CVD. No deploy by the builder.
