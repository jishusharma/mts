# ROLES: helper sessions you open by name (operator 2026-10-17)

A role = a session started with one line (`You are NAME.`); the role lives in `roles/<role>.md`, so a lost session is replaced by pasting that line again. Pinning is only a sidebar shortcut. Day-to-day recipes: MTS Home, "How to use MTS" (`scripts/dev/make_home.py`).
The role_loader hook (UserPromptSubmit) loads the file from origin/fast-track; the first reply is the `ROLE LOADED: NAME vN · token word-word · <path> @ <sha>` banner (`role_loader.py banner NAME` prints it). No banner or `ROLE NOT LOADED` = open a new session. If a file is missing locally: `git show origin/fast-track:<path>`. After a restart or clear: re-read the row, run its boot line, continue.
**No role line?** The hook picks the best-fitting operator role from the first prompt (`role_loader.py pick --text "..."`), banner `(fallback: <why>)`; embedded roles are never picked.

## Rules for every role
- Work in the `sync.py start <slug>` worktree, never the live tree; share only via `sync.py ship`; cross-machine messages only via `mts_signal.py send` (one line; long requests are a desk task).
- Opus only as in WORKERS.md rule 6; scoped sub-work to Haiku Agents (rule 3a, at most 5). Turn budget: WORKERS.md rule 5 (a Supervisor runs unattended and may auto-compact; it rebuilds from `plan`, the card board and `git cherry`).
- Roles report; they do not trade, deploy, restart, touch HALT files or read `.secrets/`.
