## Rules (frozen NK definitions; nothing re-tuned)
Source branches: `JIS-NB/nk2-pivot-sr-reclaim-1114` (PRE_REG.md, study.py), `JIS-NB/nk3-breakout-fakeout-retest-1114` (PRE_REG.md, lib.py, study.py). Differences from those studies are listed here and are the only ones.

Four rules, each trades both directions; the phase decides which direction counts:
| Rule | Trigger | Entry / stop / target |
|---|---|---|
| NK2-core | long: prev close < X <= close, X in {P, S1}; short mirror, Y in {P, R1} | next open; stop = swing of last 6 bars widened to max(0.6 x ATR14(1h simple mean), 0.5%); target = nearest standard floor pivot beyond entry (any of S3..R3), R:R >= 1; 24 bars time exit |
| NK2-deep (NEW, NK calls S3/R3 strong) | long: X in {S2, S3}; short: Y in {R2, R3} | same machinery as NK2-core |
| NK3-A | true-breakout retest: box = 20 bars before breakout bar B (width 1.5-4.0 ATR14 Wilder), B+1 takes out B's extreme, retest within 10 bars from B+2, limit at the box edge | stop = breakout candle extreme widened to max(0.6 ATR, 0.5%); target 2R; 24 bars; long in up-breaks, short in down-breaks |
| NK3-B | fakeout fade: B+1 stays inside (high <= B high and close back inside); entry at the close of B+1 against the break | same stop / target / time exit |
Pivots: standard floor pivots from the previous complete UTC day H/L/C (SOURCED NK2 PRE_REG). Levels S2/S3/R2/R3 as triggers and the **close-basis stop** are the previously untested NK items: NK2 rules use the close-basis stop (SOURCED NK "stop on closing basis": the stop fires when a bar CLOSES beyond it, exit at that close); NK3 rules use the registered intraday stop (touch, gap fills at the worse of stop and open). Step A also shows each rule on the other stop basis (column `alt_net`), so the close-basis question is answered for NK3 and the intraday question for NK2.
- Scope kept small and fixed (OURS): 1h only (15m not re-tested), exit X1 only (NK3 trail X2 and the Bollinger blast filter dropped), one position per coin per rule per direction (long and short sequences are independent, phase gating is applied AFTER the sequence so cells are not coupled).
- Same-bar stop and target: stop wins. Target fills at the level. On a limit fill bar the target is not allowed on that bar.
- Execution model: spot-equivalent round trip, no funding charge (the signals are read on spot bars). Costs: 12 bp round trip taker = 6 bp of entry notional plus 6 bp of exit notional, in R = fee / stop distance. Maker row (6 bp): the entry becomes a limit at the trigger-bar close (NK2, NK3-B) that must be traded THROUGH by the next bar (strictly), unfilled signals are dropped, stop and target are rebuilt from the fill price; NK3-A is already a limit fill, only the fee changes. Stops are still charged the maker fee (optimistic), so the maker row is a sensitivity row and is not PASS-bearing.

## Meta-label cells (spec s3, exactly)
- Step A (per-phase table first, DEV before the freeze, VAL descriptive after it): per rule x phase x direction: n, days, gross R, cost R, net R at 12 bp, plus `alt_net` on the other stop basis. Question: does the phase-appropriate direction beat the opposite one: day-clustered difference, bootstrap se, z (phases 1,2,3,5,6; ACCUM is both-sided). If no for every rule this is stated before Step B; Step B then reads as exploratory.
- Step B (DEV only): cell = (rule, phase, layer, bucket); direction = the phase's direction (both for ACCUM). Needs n >= 150 and >= 40 distinct signal days, phase DEV share >= 5%. Score = 5th percentile of the day-cluster bootstrap mean fee-net R at 12 bp (2000 draws, fixed seeds). Keep the top 3 per rule, score > 0, at most one per layer. Zero kept cells is a valid result. 144 cells per rule exist in the family; `cells_frozen.json` stores kept cells and the code commit hash; it is committed before VAL is touched.
- Step C (VAL, once, kept cells only): 12 bp primary, 6 bp maker row with the fill model above, fill ratio reported. Stats: n, days, win% and break-even win%, gross R, cost R, net R, day-cluster 95% CI (5000 draws), ex-best-5 days net R. Placebo: 1000 draws of random entries from the same cell (same phase day, bucket, direction, exit rule; hour of day matched to the real trades; pool of up to 80 simulated bars per direction and hour; for NK2 the same swing/pivot stop machinery on the random bar, for NK3 the real cell's stop-distance fractions resampled) real minus placebo and p = (1+#placebo >= real)/(1001). BH at q = 0.10 over the kept cells with the day-cluster one-sided bootstrap p (net R <= 0).
- PASS needs: net R > 0, day CI low > 0, ex-best-5 > 0, placebo p < 0.05, BH q < 0.10, n >= 150. Else FAIL, or UNDERPOWERED when n < 150. Controls per kept cell: opposite direction, the same bucket in the other 5 phases, the unconditional rule (same direction, all phases, all buckets). Report: how many DEV cells passed VAL, and DEV net vs VAL net per cell. "Beats placebo" is not "profitable": net R > 0 is required (random entries lose about 0.2 R after fees).

## Protocol and tests
- `python study.py dev` refuses to run while code/PRE_REG are uncommitted; `python study.py val` refuses unless the code is unchanged since the commit stored in `cells_frozen.json` and that file is committed.
- `test_study.py`: PHASE_LAG causal test (label for day D from data truncated at D-1), 30-day recompute of the shared phase csv, bar-phase vs truncated BTC, one future-bar poke test per context layer (8), signal truncation invariance (pivots, events, phase, context), exit-sim hand cases (close vs intraday stop, gap, tie, limit fill bar), fee and pivot formulas by hand, cell-selection rules on a synthetic planted edge, file-size check. Must FAIL under `STUDY_BUG=1` (same-day phase and pivots), `PHASE_LAG=0`, and `STUDY_BUG=2` (HTF context from the containing bar); run results are copied into RESULT.md.

## Weaknesses stated up front
- BTC-only phase: effective n is days, not signals; 40-day floor and day clusters. Four cycles: CAPITULATION and ACCUM thin; a VAL pass means surviving one regime (2024-26), not a cycle law. 144 cells x 4 rules: forking paths bounded only by DEV-only selection and BH over kept cells. No layer or threshold may be added after seeing DEV. 20 coins are correlated, so day clusters are the honest unit.
