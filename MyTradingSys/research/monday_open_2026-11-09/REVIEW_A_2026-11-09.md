## Defects

1. **monday_clocks.py cache freezes a partial bar (behavioural, medium).** `hourly()` caches the live, unfinished 1h bar, and the next run restarts at `last cached open + 1h`, so that bar is never refreshed. Evidence: cache holds the 21Z bar with close 75,690.97; the live bar later closed 75,721.04 (high/low also stale). The playbook says to re-run at 00:05Z: that re-run carries one frozen partial bar into Part 2 levels and Part 3 (the Sunday 23Z bar matters for the Sun close and the Fri-Sun low). Fix: drop the last cached bar before fetching, or cache only bars whose close time is before now. Not CI-breaking, so reported only.
2. **3-day close claim is wrong for the stated venue (clock, medium).** Section 5 says Sun 24:00 is a weekly, 2-day, 3-day and daily close. On Binance the 3d bar does not close Sunday (it closes Mon 11-09 24:00). The code prints 3-day "epoch anchor" lines as fact. Only the 5-day anchor is caveated ("anchor unstated by Krown"). Fix: mark 3-day unconfirmed, or use the venue's anchor.
3. **Absolute levels vs relative classes (consistency, medium).** The base-rate classes are relative to the Monday open (+0.8/1.4/2.6%), but the scenario lines are absolute numbers fixed from the 75,935 reading. At the 21:30Z price (75,691) the same lines are +1.14/+1.73/+2.9%, so the 70-Monday shares (B 33 / A 14 / C 29) do not describe the printed lines. The "same-setup Mondays" row should say it is by the percent rule from the actual open.
4. **Forking path in the sample.** The setup band 1.0-2.0% above the Fri-Sun low was chosen over 0.8-2.5% (n=120: B 39 (32%), A 13 (11%), C 32 (27%), chop 36 (30%)). The conclusion survives (B >= C > A, B vs C inside noise), but the playbook should say two bands were tried. Also the sweep bar's own high is excluded from the bounce (code `b[0] < end_`), while the docstring says a bar touching both levels is "counted BOTH": small mismatch in the A/B/C split.
5. **Fixed UTC session cut vs DST (minor).** `sess()` uses 14:30Z for all years; the US cash open is 13:30Z in Mar-Oct. 3 of the 116 historic sweeps (13Z bar, Mar-Oct) are labelled EU instead of US; London opens 07:00Z in summer. Effect on 65/29/22 is about 3 counts. The Monday 11-09 clock itself is correct (EST, GMT). All datetimes are UTC-aware, no naive time, no Windows timezone dependency.
6. **SOURCED labels without a quote in the evidence block.** "Krown weekly-close line 75,000 SOURCED Krown 11-05" has no verbatim quote in section 9; the only 75k quote there is Michael's. It is sourced in research/cbp/PLAN_ADX_DI_VOLUME_2026-11-07.md but not quoted. "Krown 55-day EMA 77,000", "Michael 78k higher low", "Jason 50w MA 76.9k" have no quote or data line in the playbook; 77,000 is correctly labelled OURS, so treat the Krown reference as context, not his level. No OURS parameter is called the trader's: the 76,550/77,000/77,900 steps, +0.8/1.4/2.6% thresholds, 1.0-2.0% band, day-8 conditional and 1h-close triggers are all labelled OURS.
7. **Attribution glitches (minor).** Section 9 header says "Michaal" while section 3 says "vdP" for the 11-08 "100k" quote; a "100k later" call is not a Monday-bounce call, so it should not be listed as support under scenario C.
8. **Tests.** The only test is `test_monday_clocks_percentile_and_session` in test_scenario_ledger.py: it checks `pct()` only (the name says session but `sess()` is not asserted). The file is new in this commit, so "fails on pre-change code" is trivially true and says nothing. Nothing covers `hourly()` caching, `part3` classing or the clock-anchor math, where defects 1-2 sit. All 6 tests in that file pass; test_no_own_costs passes.
