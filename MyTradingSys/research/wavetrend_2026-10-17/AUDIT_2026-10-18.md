## Finding 1 — HIGH: C1 does not implement the preregistered WT-pivot divergence

`research/wavetrend_2026-10-17/ATLAS_STUDY_SPEC.md` §2 defines C1 as a confirmed price pivot “with the WT pivot making a lower/higher extreme”; `PRE_REG.md` §6 calls it “C1 regular divergence.” In `count_events.py:181-192`, the C1 path confirms two price pivots, then compares `wt1[p]` at those price-pivot indices. It never checks that either WT value is itself a confirmed pivot. The separate `pivots(wt1 * sgn, ...)` call at lines 193-198 is used only for C2.

**Reproduction:** `python MyTradingSys/research/wavetrend_2026-10-17/repro_c1_spec_mismatch.py` prints `C1 events: [(22, 1)]` while the WT pivot list contains no pivot at either compared price-pivot index (price pivots are 10 and 20; WT pivots are 12 and 18). Thus the current detector reports a C1 event when neither paired WT value is a WT pivot. The reproduction uses synthetic arrays and reads no market data.

**Impact:** Frozen cells W07 and W08 are C1 and therefore do not estimate the preregistered divergence pattern. The two C1 rows and the descriptive C1 figures must not be used as evidence about WT-pivot divergence. The rest of the atlas and the top-level “0 of 9” screen should be described as “0 of 7 unaffected frozen cells pass; 2 C1 cells invalid under the stated event definition,” not as a complete valid 9-cell result. Do not edit/re-run the frozen study in place. Correct the event definition or detector, independently review it, and preregister a new version/trial before another DEV outcome read.

## Finding 2 — MEDIUM: control-arm uncertainty is not on the same inferential basis

The primary event arm uses day-clustered standard error (`atlas.py:132-143`). Random-clock and context-only arms instead report the standard deviation of 200 sampled draw means (`atlas.py:229-233`); `diff_test` then treats that draw variation and the clustered event-arm error as independent (`atlas.py:156-161`). This does not estimate a matched day-block contrast and does not preserve shared market-time dependence between event and control arms. `RESULT.md` already lists this as a known weakness, but the top-level per-cell z/Holm values still use it.

**Impact:** The reported p-values and Holm decisions are not a fully calibrated paired inference for the stated random-clock comparison. No cell passed even this screen, so this is not evidence of a false positive; it limits how strongly the 7 unaffected cells can be interpreted. Before drawing a stronger conclusion, freeze and review a day/block-resampling or randomization test that respects the common clock and event clustering, then register any rerun as a distinct trial.

## Finding 3 — MEDIUM: the study inputs are not content-pinned

The WaveTrend entries in `research/gross_effect_screen_2026-10-15/EXPOSURE_LEDGER.csv` identify the input as `F:/MTS/data/tom_raw/klines` and record the analysis-script SHA, but do not record a manifest/hash for the exact input files. The saved `atlas_results.json` records seed and analysis settings but also no input-file digest. The cutoff guard in `count_events.py:35-53` blocks timestamps at/after 2024-07-01; it does not establish that a subsequent run read the same pre-cutoff files or detect duplicate timestamps overwritten into the array.

**Impact:** The result can be date-bounded and still not be exactly reproducible from the repository evidence. Before another read, record each source file name, size, digest, timestamp coverage, duplicate count, missing-minute count and per-timeframe usable-bar count in a frozen manifest tied to the ledger row. Do not silently replace the current ledger row.
