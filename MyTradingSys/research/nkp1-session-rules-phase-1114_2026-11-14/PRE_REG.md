## Context
Phase = ONE label per UTC day taken from BTC and applied to all coins; label for day d uses daily closes through d-1 only (`PHASE_LAG=1`). Six phases, first match wins (all thresholds OURS, cycle state M SOURCED from the cycle-conditioned PRE_REG / BIBLE s5), built in `phases.py`:
1 CAPITULATION (M not BULL, R10<=-20%, RSI14d<=30, sticks 3 days; long) / 2 MARKDOWN (close<SMA50, S50<=-1%, and BEAR or close<SMA200; short) / 3 RELIEF (M not BULL, close>SMA20, RB30>=+12%, close<=1.05xSMA200; long) / 4 ACCUM-RANGE (M not BULL, RNG40<=30%, within 7% of SMA50, no new 60-day low in 15 days; both: long if BTC close is in the lower half of its 40-day range, short if upper half - OURS reading of "at range low and high") / 5 MARKUP (close>SMA50, S50>=+1%, close>SMA200 or BULL; long) / 6 DISTRIBUTION (everything else; short).
M: BEAR = DD<=-20% and close<SMA200; BULL = close>W200 (1400-day SMA) and DD>-20%; else BASE. Daily series: btc_cycles btc_daily.csv (blockchain.info then Binance, 2010..) extended with Binance 1d tail. Halving age is reported per phase, not used in labels. A phase with under 5% of DEV days is reported but cannot supply a kept cell. The six sanity windows of the spec are reported and NOT tuned.
Regime mix: reported in RESULT.md as the share of BTC days per phase and per M state, DEV (<=2023-12-31) and VAL (>=2024-01-01), plus trades by phase. A split with >85% in one phase is flagged ONE-REGIME. Expected plan: DEV mixes several phases; VAL is one regime (2024-26) and a VAL pass means surviving that regime, not a cycle law.

## Context layers (8, one bucket per cell, constants fixed now; `ctx.py`)
C1 4h RSI14 (<=40/mid/>=60, SOURCED Malkan 40/60); C2 1D WaveTrend LazyBear 10/21 wt1 (<=-53/mid/>=+53, SOURCED, FORMULAS s20, warm-up 200 bars); C3 4h Bollinger %B 20,2 (<0.10/mid/>0.90, period SOURCED, cutoffs OURS); C4 OI change over the last complete UTC day (<=-3%/flat/>=+3%, OURS; Binance futures metrics, last 5m row of each day); C5 mean of the last 3 funding settlements (<0 / 0..0.03% / >0.03%, OURS); C6 last complete day taker delta (2*taker_buy_vol - vol) vs price change of that day (bull-div = price down, delta>0; bear-div = price up, delta<0; else agree; spot 1d klines, OURS, fresh 24h test); C7 RV7/RV60 of daily log returns (<0.7/mid/>1.3, OURS); C8 UTC session of the session anchor (Asia 0-8 / EU 8-16 / US 16-24, OURS; near-constant per variant so it acts as the phase-only cell).
All layers read values only when available at the anchor time (last closed 4h/1d bar, last published OI/funding). Coins/dates without futures data have no C4/C5 bucket (bucket = NO-DATA, excluded from cells); coverage per layer is reported. Futures data starts when Binance published metrics (probed per coin and reported); `layer_coverage.csv`.

## Rules and variants (taker 12 bp primary; cost = 12 bp + funding paid while held)
Each variant is its own "rule" for selection (max 3 cells each), 4 variants, so at most 12 kept cells; BH q=0.10 runs over all kept cells.
- NK1-UTC / NK1-NY: ported unchanged from `JIS-NB/nk1-first-hour-low-break-vwap-1114` (opening range first 15 min, break in b3..b11, close back, no big candle <=2.5x mean range, entry at next open when close within 0.1% of session VWAP; stop = break low, min distance max(0.5%, 0.6xATR14(5m))). Exit E3 = session end only (UTC 00:00-12:00; NY 09:30-16:00 NY). E1/E2 exits are DROPPED (they multiply cells). Gaps fill at the worse price. 6 bp maker row with fill model: limit at the close of the signal bar, fills only if the next bar trades through it.
- NK5-NYasia / NK5-UTC4h: ported from `JIS-NB/nk5-session-open-15-10-5-1114` (15m RSI14 touch <=35 / >=65, 10m and 5m Hilega Milega RSI9 EMA3 vs WMA21 [OURS], anchor NY close 16:00 NY -> hold to 08:00 UTC; anchor 00:00 UTC hold 4h; stop max(0.5%, 0.6xATR14 1h); gap-aware fill). The other 3 old NK5 rows are DROPPED. Maker row: limit at the prior 5m close, fills only if the anchor bar trades through it.
Signals in the phase-appropriate direction only are trades; the opposite direction is a CONTROL.

## Step A (per-phase table, headline = none)
For every variant x phase: appropriate vs opposite direction, DEV and VAL: n, days, gross R, cost R, net R, and appropriate-minus-opposite difference with day-cluster SE (SEs added in quadrature; same-day correlation ignored). No pooled-phase headline is printed.

## Step B (selection on DEV only, `analyze.py select`)
Cell = phase x one layer x one bucket, direction = the phase-appropriate side. Needs n>=150 signals and >=40 distinct days on DEV (<=2023-12-31, by signal-bar day). Score = lower 90% bound (mean - 1.2816 x day-cluster SE, ratio estimator by UTC date) of the net R at 12 bp + funding. Keep the top 3 per variant with score>0, at most one cell per layer, from phases with >=5% of DEV days. Zero kept cells is a valid result. The selection stage reads DEV rows only (assert in code), writes `cells_frozen.json` with the commit hash of the code, and that file is committed BEFORE `analyze.py val` runs. (Disclosure: the per-coin candidate cache contains VAL trades because it covers all dates; no VAL statistic is computed or read before the freeze.)

## Step C (VAL, once, kept cells only)
12 bp + funding primary; 6 bp maker row with the fill model (descriptive, no placebo claim). Stop >= max(0.6xATR, 0.5%), gaps at the worse price. Statistics per kept cell: day-cluster bootstrap 95% CI (2000 resamples, seed 1114), mean net R excluding the best 5 days, placebo = 1000 draws of n random entries from the same cell (same variant, phase, bucket and phase-appropriate side; same hour because the session anchor is fixed; NK1 draws a random entry bar among b3..b12 with the same structural/min-stop rule), p = share of draws >= real mean; BH q=0.10 over kept-cell bootstrap p-values.
PASS needs: net R>0, CI low>0, ex-best-5>0, placebo p<0.05, BH q<0.10 and n>=150. n<150 = UNDERPOWERED, otherwise FAIL. Control rows per cell: opposite direction (same phase+bucket), same bucket in the other 5 phases (phase-appropriate direction), the unconditional rule (all phase-appropriate signals). Reported: how many DEV-kept cells pass VAL and DEV-to-VAL shrinkage per cell. Verdict line: PASS if any cell passes, else FAIL (or NO KEPT CELLS).
