# MTS_Doctor report 2026-10-19: ship-gate speed and cost (fast path bd1b0c7d, Codex verification 1d746fec)

Scope: the ship-time work delivered 2026-10-18/19. Claude built the fast ship gate (X1-X6, `GATE_SPEED.md`); GPT/Codex then ran an independent
verification (`research/shipping_speed_2026-10-19/`). No Gemini deliverable on shipping cost or time exists on trunk (searched cards, commits, desk

## Verdict
- Codex's PROOF.md is accurate and honestly negative: 187 regression tests pass; one sequential pair measured old smoke 23.022 s vs fast 25.794 s
  (12.04% slower), so the 50% target (11.511 s) is NOT shown. Haiku re-checked every number against the logs: 7 of 8 claims exact (arithmetic,
  28 files / 19 kept / 13 deferred, 21.7 s step, six baseline steps, source hashes match HEAD, no CRLF).
- The fast gate is faster than the FULL gate (about 544 s -> 24-51 s on the two measured ships) because of selection and caching. Against the old SMOKE
  gate the gain is small or absent for a hub-reached file: GATE_SPEED.md's own numbers are 55 s smoke vs 51.3 s fast for `nowin.py` (about 7%, and the
  55 s excludes fetch/push overhead that the 51.3 s includes). The 23.8 s `make_home.py` ship has a different workload (1 test file) and proves nothing about speed-up.
- Cost: Sonnet's diff review estimates 60-70% of the gain is fewer tests run (a quality trade, CI runs them minutes later) and 30-40% is engineering
  (wiring_scan cache 17 s -> 1.5 s, own slot pool, threads). Not measured per source; treat as an estimate.
- The doctor's own re-measurement was NOT possible: the box was at 100% CPU and both fast slots (`gate-slots-fast/slot-0` pid 2100 since 02:19,
  `slot-1` pid 7952) were held by other sessions' ships for 20+ min, so a `--slot` run waited in the queue. Wall times taken then would have measured
  the queue. Two timing runs were started by mistake in parallel and killed; nothing from them is used. The Codex single pair therefore stands
  unrefuted and unconfirmed. Lesson: the fast pool starves under load, which is what card `sv7-host-gate-budget` is meant to fix; it is still open.

## Recommendation
Keep the fast path; fix #1 before relying on it (run 3dl when any `.py` or `ci.yml` changes, +3 s). Do not advertise "50% faster than smoke":
the evidence supports "much faster than full, about equal to smoke on hub files". Persist the deferred list (#2). Re-measure only on an idle host
with an empty fast pool, 3+ alternating pairs, and record host and load.
