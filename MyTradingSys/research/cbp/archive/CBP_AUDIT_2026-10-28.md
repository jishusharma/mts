## 1. Executive Summary (Answers to Operator Questions)

### Q1: How is CBP integration going as a module of MTS?
- **Architecture is simplified and landed (`D5_CBP_MODULE.md:6-20`)**: The legacy multi-hop queue (`mts_queue/pending.json`, `acks/`, `consumer.py`, `cbp_adapter.py`) was retired and deleted (`f9fcf77b4`, CBP `7d2937b`).
- **Single MTS Producer Entry (`scripts/dev/cbp_run.py`)**: Fetches captions from the 6 enabled `actionable` analysts (Krown, Rekt, Jason, Michael, Michaal, Qriptal) over a 5-day rolling window via `fetch_captions_timed.py` (with `youtube-transcript-api` fallback on HTTP 429), runs one `claude -p` pass per new video, verifies every quote verbatim via `verify_extract_quotes.py`, deduplicates on `(video_id, analyst)`, and writes `cbp_store/rows.json`.
- **Single MTS Consumer Read Path (`MyTradingSys/cbp/__init__.py`)**: `cbp.query(analyst=None, symbol=None, since_days=5)` reads `cbp_store/rows.json` and fails closed on schema violations (`validate_row`), invalid trade directions (`LONG`/`SHORT` enum), or expired rows (`expires_at <= now` or `published < cutoff`).

### Q2: Do we have a way to run the CBP module every day / twice a day? How is MTS controlling it?
- **Yes, two mechanisms exist under MTS control (CBP never self-schedules)**:
  1. **Twice-daily Windows Task (`scripts/dev/cbp_schedule.py`)**: Authorized as the sole CBP-only exception in `SCHEDULING_POLICY.md:40-51`. Defines Windows Scheduled Task `MTS-CBP-Ingestion` firing daily (including weekends) at **09:00 UTC** (`EU` window `09:00–13:00 UTC`) and **13:00 UTC** (`PRE_US` window `13:00–24:00 UTC`), with 3x15m failure retries, `IgnoreNew` overlap protection, and `StartWhenAvailable` wake catch-up. It invokes `python scripts/dev/cbp_run.py --due`.
  2. **Coordinator / Operator Invocation (`scripts/dev/cbp_run.py --due | --force`)**: On each wake, the MTS coordinator can call `cbp_run.py --due` (which checks `cbp_store/stamp.json` so each UTC window runs at most once per day), or the operator can run `cbp_run.py --force` at any time.

### Q4: Are all the traits CBP provides on a daily basis wired into MTS layers?
- **Storage & Query Traits Are Wired**: Every daily row provides `analyst`, `video_id`, `published`, `bias` (`BULLISH|BEARISH|NEUTRAL|NO_VIEW`), `symbols[]`, verbatim `quotes[]`, `trades[]` (`asset`, `direction`, `entry`, `target`, `invalidation`, `quote`), `pointers[]`, `quote_verified`, and `expires_at`. `cbp.query()` and `cbp.is_tradable()` expose these cleanly.
- **Downstream Strategy / Trading Layers Are NOT Wired Yet (Intentional Gate 4 & Gate 5)**:
  - A full-repo scan (`git grep "cbp.query"`) confirms **zero production layers or `auto_trader.py` modules call `cbp.query()`**.
  - Per `D5_CBP_MODULE.md:19,45-54` and `SCORECARD_GPT.md`: CBP rows are *claims, not signals*. **Gate 4 (Scorecard)** requires >= 56 scored calls per analyst before any weight is assigned (all analysts currently have < 56 calls -> `NOT ENOUGH CALLS`), and **Gate 5 (Promotion / B139)** requires a pre-registered backtest passing `VALIDATION` before any layer can trade.
  - Meanwhile, the Krown technical indicator layer (`MyTradingSys/backtest/layers/krown/`) computes rules directly from closed OHLCV bars (`krown_core.py`, `krown_events.py`, `krown_context.py`, `enabled: false`), independent of daily YouTube commentary.

## 3. How to Activate Twice-Daily Runs on This Machine (or JIS-NB)

To turn on live twice-daily automatic runs (`09:00` and `13:00 UTC`):
1. Ensure the CBP v2 config (`cbp_v2/analysts.json` from `origin/cloud/work` of `CryptoScrapper`) is checked out at `F:/CryptoScrapper` (or set `CBP_HOME` / populate `runtime_data/cbp/cbp_v2/analysts.json`).
2. Run preflight, one initial run, and task registration from the durable checkout:
   ```powershell
   python scripts/dev/cbp_schedule.py check --home F:/CryptoScrapper
   python scripts/dev/cbp_schedule.py run --home F:/CryptoScrapper
   python scripts/dev/cbp_schedule.py install --home F:/CryptoScrapper
   python scripts/dev/cbp_schedule.py status
   ```
3. Until an analyst accumulates **56 scored calls** (`D5` Gate 4) and passes a **pre-registered backtest** (`D5` Gate 5), daily rows populate `cbp_store/rows.json` for research/desk display and scorecard tracking without triggering live orders.
