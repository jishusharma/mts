## What the code respects (so the table is fair)

- Fabio v3 does respect NY-window, weekdays, US_CLOSED, entry cutoff open+330, a day gate on range vs prior 20 weekdays, first-leg stops and a daily -3R stop (`day_gates.py`). Weekends are excluded by construction (`ny_open_utc` returns None).
- `census_session_ladder.py` filters weekdays and uses DST-aware DAX and NY blocks; it uses an HTF ladder gate (align_n >= 2) that is a context filter, not a balance/trend filter.
- `is_knife_approach` fails closed (`auction_context.py:526-537`). `prior_ny_session_profile` is correct and tested; it is just unused (G02).
- Not respected by any code found: cash-session-only value source for the studies (G01-G03), skip first 30 minutes (G04), opening-range gate (G05), regime-conditional return probability (G06), day-bias gate (G09), choppy/absorbed-day filter on Model B (G10), acceptance exit (G19), volatility regime (G24).

## Top 5 gaps (by size of consequence)

1. **G01 + G02**: Tom says a cash-session trader who uses 24-hour profiles is doing something "inherently quite meaningless". All BTC value-area work is 24h UTC. The fix exists as code (`prior_ny_session_profile`) and nobody calls it. This also reverses the framing in FACTS B2: the UTC-day result is not a weaker copy of his test, it is the thing he warns against.
2. **G13**: Fabio says both "I don't use order flow on Bitcoin" and "I do crypto order flow, extremely profitable, on Saturdays". Iteration 1 recorded "0 hits" for crypto, so the only first-hand statement on the transfer question is missing from every document.
3. **G09 + G10**: Fabio takes only bias-aligned setups and skips choppy/absorbed days ("the worst market condition you can get for my strategy"). Our Model B and absorption signals fire on every day type, both sides.
4. **G06 + G08**: Tom's 70% return and his setups are phase-conditional ("when a market becomes strongly trending, please stop trying to get back", "Breakout trading only works when a market is out of balance"). Every count we ran was unconditional on phase.
5. **G04 + G05**: Tom says to stop trading the first 30 minutes of the NY session and to read the opening range size; the session census includes the window and ignores range size.

## Single biggest hole

Our value area is built from a window (24h UTC day or Monday-week) that the trader says is meaningless for a trader who uses a session, and the corrected window already exists in `auction_context.prior_ny_session_profile` but no census or study reads it. Until the return-to-value count and the census run on NY-session value (weekdays, first 30 minutes skipped), the 57.2% vs 70% comparison and the "no edge" verdicts built on it do not test his claim.
